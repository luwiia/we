# Cargo Load Estimator: Автоматическая оценка процента загрузки кузова транспорта по фото

## 1. Executive Summary (Краткое резюме)
**Cargo Load Estimator** — высокопроизводительный сервис на базе Computer Vision и глубокого обучения, разработанный для решения задачи контроля загрузки автотранспорта. Сервис производит автоматическую оценку процента заполнения кузова или прицепа (от 0% до 100%) по одной фотографии.

* **Бизнес-эффект:** Исключение ручной проверки фотографий, автоматизация сопоставления фактической загрузки с накладными на сортировочных центрах и КПП, ускорение формирования отчётности.
* **Архитектурный подход:** Взвешенный ансамбль из 10 моделей (5× EfficientNet-B3 + 5× EfficientNet-B5) с 4-компонентным Test-Time Augmentation (TTA), экспортированный в формат ONNX для ускорения на CPU в 1.85 раза без потерь в качестве.
* **Итоговые метрики:**
  * **OOF MAE:** **4.671 п.п.** (улучшение относительно baseline в **×4.09 раза**).
  * **Median AE:** **2.878 п.п.**
  * **Within-10% (ошибка ≤ 10 п.п.):** **88.3%**.
  * **Инференс на CPU:** **~2.55–2.9 сек** на кадр с полным 10-модельным ансамблем и TTA (против ~5.3 сек на PyTorch).

## 3. Архитектура решения и пайплайн

### 3.1. Предобработка изображений
1. **Паддинг до аспекта 3:4 (`pad_to_ratio`):** Дополнение кадра краевыми пикселями (`BORDER_REPLICATE`) сохраняет исходную перспективу и геометрию фургона.
2. **CLAHE:** Контрастно-ограниченное выравнивание гистограммы (`clip_limit=2.0`, `grid=8x8`) на L-канале пространства LAB для проявления затемнённых зон в глубине кузова.
3. **Ресайз:** Приведение к разрешению 384×512 (для B3) и 448×596 (для B5) строго через `cv2.INTER_LINEAR` (обеспечивает полное совпадение с аугментациями Albumentations).
4. **Нормализация ImageNet:** μ = [0.485, 0.456, 0.406], σ = [0.229, 0.224, 0.225].

### 3.2. Архитектура нейросети
* **Backbone:** Предобученные веса ImageNet (`timm`).
* **Голова:** `AdaptiveAvgPool2d` → `Dropout(0.3)` → `Linear(in_features, 1)` → `Sigmoid()`.
* **Ансамблирование:** Взвешенное среднее предсказаний:
  Pred = 0.4 * B3 + 0.6 * B5
* **Enhanced TTA (4 прогона):** Исходный кадр, горизонтальный переворот (`HorizontalFlip`), центральный кроп 90% с ресайзом и мультимасштабирование (0.9x).

### 3.3. Параметры обучения (PyTorch)
* **Loss:** `L1Loss` (MAE).
* **Оптимизатор:** `AdamW` (`weight_decay=1e-4`).
* **Warmup:** 2 эпохи обучения классификатора (`lr=1e-3`), далее сквозное обучение: `lr=3e-4` (для B3) и `lr=1e-4` (для B5) с `CosineAnnealingLR`.
* **Ранняя остановка:** `EarlyStopping(patience=6)`.

## 4. ONNX-оптимизация и бенчмарки скорости

Все 10 обученных сетей экспортированы в формат ONNX (`opset_version=17`). В продакшене используется только библиотека `onnxruntime`, что исключает необходимость запуска тяжёлого PyTorch-рантайма на сервере.

### 4.1. Бенчмарк производительности (CPU: 8 ядер / 16 потоков, Windows)

| Метрика | PyTorch | ONNX Runtime | Эффект |
| :--- | :---: | :---: | :---: |
| **Холодный старт (загрузка 10 моделей)** | 2.8 сек | **1.8 сек** | Загрузка один раз при старте сервиса |
| **Инференс 1 фото (10 моделей + 4-way TTA)** | 5.3 сек | **2.9 сек** | **Ускорение в 1.85 раза** |
| **Пропускная способность** | 0.19 фото/с | **0.35 фото/с** | Рост пропускной способности на 85% |
| **Пакетный прогон всего теста (307 фото)** | ~27 мин | **13.1 мин (784 с)** | **Среднее время на кадр: 2553 мс** |

> **Точность ONNX:** Максимальное расхождение с расчётами PyTorch на контрольной выборке составляет ≤ 0.2 п.п. (среднее расхождение ± 0.11 п.п.), итоговый OOF MAE (4.671) полностью сохранён.

## 5. Документация XML API

Микросервис реализован на базе FastAPI с поддержкой XML-формата входящих запросов и ответов, кэшированием сессий моделей и сохранением истории в SQLite (WAL mode).

### 5.1. Расчёт процента загрузки (`POST /api/v1/predictions`)
* **Headers:** `Content-Type: application/xml` или `multipart/form-data`.
* **Кэширование:** При повторном запросе с тем же `shipmentId` и идентичным SHA256-хэшем изображения сервис отдаёт результат из локальной БД (`status 200 OK`, `<cached>true</cached>`) за 0 мс без повторного инференса.

**Пример запроса (XML):**
```xml
<?xml version="1.0" encoding="UTF-8"?>
<predictionRequest>
    <shipmentId>TRUCK_2026_09_001</shipmentId>
    <image>/9j/4AAQSkZJRgABAQEASABIAAD...</image>
</predictionRequest>
Пример ответа (XML, HTTP 201 Created / 200 OK):

XML
<?xml version="1.0" encoding="UTF-8"?>
<prediction>
    <shipmentId>TRUCK_2026_09_001</shipmentId>
    <version>1</version>
    <loadPct>95.96</loadPct>
    <modelVersion>ens-10-onnx-b3-b5</modelVersion>
    <createdAt>2026-09-22T19:00:00Z</createdAt>
    <cached>false</cached>
</prediction>
5.2. Подтверждение оценки экспертом (PUT /api/v1/shipments/{shipment_id}/confirmed-load)
Позволяет оператору/логисту зафиксировать фактическую загрузку кузова для формирования обучающего пула.

XML
<?xml version="1.0" encoding="UTF-8"?>
<confirmation>
    <loadPct>95.00</loadPct>
</confirmation>

7. Инструкция по запуску (Quickstart)
7.1. Установка окружения
Bash
# Клонирование и переход в проект
git clone [https://github.com/your-org/cargo-load-estimator.git](https://github.com/your-org/cargo-load-estimator.git)
cd cargo-load-estimator

# Виртуальное окружение
python -m venv venv
# Linux:
source venv/bin/activate
# Windows:
# .\venv\Scripts\Activate.ps1

pip install --upgrade pip
pip install -r requirements.txt
7.2. Инференс и сабмит через ONNX
Bash
# Инференс одного тестового снимка
python -m src.predict_onnx --image test/images/img_00b135ede40393ac4459.jpg

# Формирование итогового submission_onnx.csv (307 фото, ~13 минут на CPU)
python -m src.predict_onnx --all
7.3. Запуск веб-сервиса
Bash
# Локальный старт FastAPI через Uvicorn
uvicorn api.app:app --host 0.0.0.0 --port 8000 --workers 1

# Запуск в Docker Compose
docker compose up --build -d

# Проверка статуса
curl http://localhost:8000/api/v1/health
7.4. Дообучение модели на новых данных
Bash
python -m src.finetune --csv new_data.csv --images new_images/ --epochs 5
Скрипт выполняет дообучение весов с пониженным шагом (lr=1e-5), снижая MAE на контрольной выборке на ~1.15 п.п.
